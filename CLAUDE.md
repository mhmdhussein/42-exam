# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An offline simulator for the 42 exams (Exam Ranks 02–06 and Piscine exams), derived from jcluzet/42_EXAM. A C++ "examshell" binary draws random exercises, and bash testers grade the student's submission against a reference solution. Runs on Linux/WSL only (`launch.sh` refuses anything else; on Windows, build and run `make`/`check-subjects` inside WSL); needs `gcc`, `g++`, `clang`, `make`, and readline headers.

## Commands

```sh
make                 # build .system/a.out and start it via .system/launch.sh
make build           # build only (c++ -std=c++11 -Wall -Wextra -Werror, links -lreadline)
make re              # rebuild from scratch
make check-subjects  # validate every exercise (see below)
make reset           # delete session state: rendu/ subjects/ success/ traces/ .system/grading, saved token
```

The simulator version lives in `VERSION` (one line, e.g. `3.0.0`); the Makefile passes it as `EXAMSHELL_VERSION` (`dev` without the file) and rebuilds when it changes. It is shown on both login screens. Bump it for a release instead of editing the code.

Check a single exercise or subset: `bash .system/check_subjects.sh <substring-of-path>` (e.g. `exam_02/first_word`). Env vars `JOBS` (parallelism) and `TIMEOUT` (seconds per tester, default 180). Each result is `OK`, `BROKEN` (reference fails its own tester), `WEAK` (empty submission passes), `LEAKY` (a known-wrong solution in `wrong/` passes), or `NO_TESTER`; it exits non-zero on `BROKEN`, `WEAK` or `LEAKY`.

## Architecture

- **C++ examshell** (`.system/*.cpp`, headers `exam.hpp`/`exercise.hpp`): menus (`menu.cpp`), the `exam` class with prompt loop, levels, cooldown and cheat commands (`exam.cpp`), exercise preparation — copies the subject into `subjects/` and tester files into `.system/grading/` (`exercise.cpp`), grading (`grade_request.cpp` runs `bash .system/grading/tester.sh` and checks for `.system/grading/passed`, saving traces to `traces/` and passing work to `success/`), and save/restore of exam state and settings under `.system/exam_token/` (`data_persistence.cpp`). Practice mode (main menu entry 3: live termios search picker with a line-mode fallback, `practice>` prompt, passes logged to `success/practice_ex`, never writes the exam token) lives in `practice.cpp`; grading shared with the exam goes through `exam::run_tester()`. It shells out heavily via `system()`; all paths are relative to the repo root, so the binary must run from there. `start_new_ex()` calls itself once per level, so the `finish` command and the end of an exam (after the summary and an Enter) throw `exam_finished`, which `main()` catches to reset the session (`exam::reset_session()`) and reopen the menus; `exit`/`quit` still `exit(0)`.
- **Display layer** (`display.hpp`, `display_modern.cpp`, `display_legacy.cpp`, `display_examshell.cpp`): the exam logic changes state; everything it shows or asks goes through the abstract `Display` held in `exam::display`. The exam fills plain structs (`ExamView`, `GradeResult`, `ExamSummary`, `SettingsView`, `RestoreView`) and the display only reads them. The prompt loop asks `display->readCommand(make_view())` for an `Action` instead of comparing strings itself, and fixed one-liners go through `message(Msg)`. `make_display()` maps the "Display style" setting to `ModernDisplay` (default, `display_modern.cpp`, built on `ui::` with raw-key menus that fall back to typed numbers without a terminal), `LegacyDisplay`, `ExamshellDisplay` (Legacy that only overrides `showStatus`) or `DashboardDisplay` (see below); `exam::set_display()` re-picks it whenever settings are loaded or saved. A new look is a new `Display` subclass implementing every method, plus a case in `make_display()`. Displays that read with `cin >>` eat their own trailing newline (the exam never calls `cin.ignore()`). `run_tester()` fills `exam::last_result` (`GradeResult`, including the trace parsed from the `docs/TESTER_GUIDE.md` format) and the caller shows it; `testerStarted`/`testerFinished` wrap the tester run (Modern's spinner polls `.system/grading/progress`). `current_token.txt` ends with the passed levels (`level name failed_tries passed_at`); older tokens without them still restore. Practice mode's screens go through it too (`practiceGuard`, `practicePicker`, `practiceStatus`, `practiceCommand`, `practicePassed`, ...; `practice.cpp` keeps the index, the filter and the grading). Only the signal handlers in `utils.cpp` and fatal errors still print directly.
- **Terminal and UI toolkit:** `term.cpp`/`term.hpp` holds terminal info (`term_width`, `term_color` = stdout is a TTY and `NO_COLOR` unset, `term_unicode` = UTF-8 locale and `EXAMSHELL_ASCII` not 1), raw-mode key reading (`term_raw_enter`/`term_raw_restore`/`term_read_key`/`term_read_key_timeout`, also restored by the signal handlers) and the full screen (`term_screen_enter`/`term_screen_leave`, `term_resized`, `term_write`). `ui.cpp`/`ui.hpp` (namespace `ui`) holds the building blocks for modern screens: palette (`paint(Color, …)` instead of raw `LIME`/`RED`), symbols with ASCII fallbacks, `box`, `divider`, `columns`, `progress`, and a threaded `Spinner`. Widths are measured on screen (escape codes skipped, one per UTF-8 character).
- **Dashboard** (`display_dashboard.cpp`, `DashboardDisplay : ModernDisplay`): the exam on one full screen; only the in-exam methods are overridden, everything else (menus, Settings, end summary, Practice) is Modern's on the normal screen. Its state lives in a file-static struct because `load_settings()` recreates the display at every level and after Settings. Modern helpers it shares are declared in `display_parts.hpp` (namespace `modern`, including `result_lines()`, the result card content). Drawing goes through `ui::Screen` (`ui_screen.cpp`: cell grid, `flush()` sends only the changed cells in one `term_write()`; `panel`, `text`, `wrap`, `split_h`/`split_v`). Full-screen rules: `term_screen_enter()` keeps raw mode on until `term_screen_leave()` (never toggle it per key: `TCSAFLUSH` drops typed-ahead keys); always leave full screen before exiting or showing a non-dashboard screen (`sigc`/`sigd`, `atexit`, fatal errors and `make_display()` for other styles already do); draw only from the key loop (`waitKey`: 1 s clock ticks, `SIGWINCH` only sets a flag) or the grading spinner, both under `draw_mutex_`; the tester runs with stdin/stdout/stderr on `/dev/null` (`term_quiet_begin`/`term_quiet_end`). Falls back to Modern without a terminal or under 80×24 at the start.
- **Exercises** live at `.subjects/<STUD_PART|PISCINE_PART>/exam_0X/<level>/<name>/` with `attachment/subject.en.txt` (+ any given files), reference `<name>.c` (or several files / `.cpp`), `main.c` for function exercises, `cases`, optional `allowed`, `config`, `inputs/`, `wrong/` (known-wrong solutions that must fail), a `tester.sh` only for custom testers, and optional `beta` (contributor name → "beta exercise" warning). `check_subjects.sh` finds exercises at exactly depth 4 under `.subjects`.
- **Tester protocol**: grading runs the exercise's `tester.sh` if it has one, otherwise the shared runner `bash .system/run_tests.sh <name>` (both from the repo root, with the exercise files copied to `.system/grading/`). The runner builds reference and student (`rendu/<name>/`, same file names) in `build_ref`/`build_stud` with `-Wall -Wextra -Werror` (`c++ -std=c++98` if there is any `.cpp`), checks `nm -u` against `allowed`, runs each line of `cases` under `timeout` and compares `cat -e` stdout (plus exit code / stderr / leaks if `config` says so). On failure it writes `traceback` at the repo root (format from `.system/trace.sh`) and exits 1; on success it touches `.system/grading/passed`. Custom `tester.sh` files (only where `cases` can't express the exercise) follow the same contract and source `.system/trace.sh`. All testers must follow [docs/TESTER_GUIDE.md](docs/TESTER_GUIDE.md) (flags, allowed functions, pass/fail, trace format, `cases`/`config` syntax, edge cases, definition of done); run `check-subjects` on them.

`plans/REMOVED_FEATURES.md` documents features dropped from the upstream project.
